# Jump to Reach the Sky — BACKEND (game server)

Frontend (3D client) lives at `../Jump-to-reach-the-sky` (its `src/net.js` is the other half of this contract). Colyseus + Mongo. The server was ported from Bowling Roll; everything of the old boat game (boats, engines, pets, races, spin wheel, presence) is gone.

- `npm start` (tsx watch, port 2567), `npm run build` (tsc -> `build/`), `npm test` (mocha + `@colyseus/testing`, Mongo faked via `__setPlayersForTest`; tests share one booted server, `test/server.ts`). Node >= 22.
- One room, `world` (`src/rooms/WorldRoom.ts`, client calls `joinOrCreate("world", { userId, username, pfp })`). **Room size = the number of bases in the hub**: `ROOM_MAX_CLIENTS` (`src/constants.ts`) = the client's `HUB.plots.count` (6). Every player gets a free base, `seat` (0..5, west -> east, the roster's `PlayerState.seat`), and the client builds that plot as its own (`HUB.plots.local`, spawn and the Home teleport follow it). A seat is freed when its player leaves for good (a dropped connection keeps it for `RECONNECT_SECONDS`). A seventh player is refused and the Legion matchmaker opens another pod.
- Client-authoritative: the server only bounds/sanitises saves (`src/sanitize.ts`). `src/db.ts` degrades to "no persistence" when `MONGODB_URI` is unset/unreachable; guests (`guest-` ids) are never saved. `/health` for Legion; `/monitor` and the playground are dev-only.
- Messages client -> server: `sync` (sent once the client's handlers exist and after every reconnect; messages the server sends from `onJoin` would be dropped, so the first answer waits for it), `saveProgress` (the whole snapshot, throttled client-side), `identify` (`{ userId, username, pfp }` after a sign-in/out mid-session), `claimDaily` (`{ all?: boolean }`).
- Server -> client (private): `progress` / `noProgress` / `serverError`, each with `seat` and `serverTime` (the saved doc sanitized / a new account, guest or no database: the client keeps its fresh state and saves it / the save could not be read: saving stays off so it is never overwritten); `daily`; `dailyResult`; `leaderboard`. Saves are ignored until the session's load has answered (`loaded`). A second live session on the same account is evicted. Roster (`PlayerState`): `username`, `signedIn`, `pfp`, `seat`.
- Saved progress shape (`PlayerDoc` in `src/db.ts`, client `src/game/state.js` `SAVED` + `t` -> `lastSeen`): `money`, `totalEarned`, `jumpPower`, `rebirths`, `slotsUnlocked`, `slots[] { species, variant, bank?, income? } | null` (by pedestal), `pads[]`, `skips[]`, `bestZone`, `index { species: { variant: true } }`, `perks { id: true }`, `boosts { id: seconds }`, `smartJump`, `carried[]`, `speed`, `carryMax`, `luckyJumps`, `items { id: true }` + `equipped` (must be owned), `dailyPass`, `dailyMilestones { day: true }`, `lastSeen` (offline income counts from it). Money and Jump Power go up to ~1e41, bound `NUMBER_MAX` = 1e100. Ids match `ID_PATTERN`.
- Daily Rewards (`src/daily.ts`, constants `DAILY_*`): server-authoritative on the server clock. One claim per `DAILY_COOLDOWN_MS` (20 h), a gap over `DAILY_STREAK_BREAK_MS` (48 h) restarts at Day 1 (and clears `dailyMilestones`), the cycle is `DAILY_CYCLE` = 7 days. The Claim All Pass (`dailyPass`, saved by the client) lets mid-week days be claimed without waiting and `{ all: true }` claims the rest of the week. Doc fields `dailyDay` (streak days claimed) and `dailyAt` (ms of the last claim) are written only by the server, never by `saveProgress`. `daily` { day, at, cooldownMs, serverTime, reset } is sent after the load; `claimDaily` answers `dailyResult` { ok, count, reason?: "loading" | "locked" | "save", reset, day, at, cooldownMs, serverTime } (ok only once stored). Guests / no-DB sessions keep theirs in memory for the connection.
- Leaderboards (`src/leaderboard.ts`): the hub's two boards (client `hub/leaders.js`). Top `LEADERBOARD_SIZE` (16) saved players by each of `LEADERBOARD_STATS` (`totalEarned`, `jumpPower`), read into one process-wide cache refreshed at most every `LEADERBOARD_EVERY_MS`; each player's own rank = countDocuments(stat > theirs) + 1 (null for guests / no score). Server -> client `leaderboard` { boards: { stat: [{ name, value }] }, ranks: { stat: n | null } }, sent after each load and to everyone every `LEADERBOARD_EVERY_MS`. `connectDb` creates a descending index per stat.
- `src/constants.ts` bounds must cover the client's `src/config.js` (list sizes, ids). A contract change goes in both projects.
- CI/CD: `.github/workflows/deploy.yml` tests on PRs and pushes to `main`/`dev`; pushes also build+push a GHCR image and deploy to Bloxity Legion (`main` = prod, `dev` = dev; docs: hosting.bloxity.io/docs), sending `seatCap` = `ROOM_MAX_CLIENTS` read from `src/constants.ts` (the docs require it to equal the room's `maxClients`). Clients must reach the server through the matchmaker (`Legion.SDK.net.resolveEndpoint`), never the host URL. Needs repo var/secret `LEGION_GAME_ID` (= the client's `GAME_SLUG`) and secret `LEGION_DEPLOY_TOKEN`.
